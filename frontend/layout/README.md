# Сторож раскладки

Единственная проверка в проекте, которая видит **результат** вёрстки, а не намерение.

## Зачем он есть

Остальные 338 сторожей проверяют, какое свойство выставлено и какой класс навешен.
jsdom вёрстку не считает вовсе — ни ширин, ни переносов, ни переполнений. Поэтому
редизайн уехал в бой с зелёным прогоном из 2564 тестов, а двадцать бед адаптива
прожили в продукте незамеченными: «съехало» — это результат, и до сих пор его не
мерил никто.

Здесь боевой CSS и настоящая разметка открываются в настоящем Chromium на матрице
размеров при обеих рельсах, и три признака считаются арифметикой.

## Как запускать

```sh
cd frontend
npm run layout        # полный прогон: сборка → снимки → стенды → замер (~1,5 мин)
npm run layout:fast   # то же без пересборки CSS (~15 с) — для правок самой проверки
```

Прогон **не входит** в `npm test`: браузер медленный, а обычные тесты обязаны
оставаться быстрыми. Имя файла проверки — `раскладка.pw.ts`, а не `*.spec.ts`,
именно поэтому: vitest забирает `*.spec.*` в общий прогон по умолчанию.

Порт стенда — 8742, меняется через `LAYOUT_PORT`. Сервер поднимается и гасится сам.

## Что проверяется

| Признак | Когда считается бедой |
|---|---|
| **режется** | `scrollWidth − clientWidth > 1` и блок ОБРЕЗАЕТ (`overflow: hidden/clip`) без многоточия и без прокрутки — текст исчез, и человеку об этом не сказали |
| **наезд по высоте** | дети вылезли за нижний край блока, блок не прокручивается И (режет содержимое ИЛИ под ним есть брат) — строки лягут поверх соседа |
| **вылез вправо** | правый край за правым краем родителя больше чем на 1.5px, и ни один предок не прокручивается вбок |
| **полоса у страницы** | у документа появилась горизонтальная полоса |

Матрица: 16 ширин от 320 до 2560 (высоты взяты от реальных окон: у ноутбука
1366×768 на страницу остаётся ≈700 CSS-пикселей). Каждый экран рабочего места
гоняется при **обеих** рельсах — развёрнутой 218 и свёрнутой 72.

## Чего он не видит — честно

1. **Положение выпадающих панелей.** Координаты им считает floating-ui по настоящим
   размерам якоря; в снимке из jsdom размеры нулевые, и панель стоит у левого
   верхнего угла. Меряется её собственная ширина и текст внутри — не то, вылезет ли
   она за край окна.
2. **Цвет и читаемость.** Это `src/test/tokenContrast.test.ts`.
3. **Поведение.** Наведение, фокус, анимации: снимок — это один кадр покоя.
4. **Светлую тему.** Меряется тёмная. Это законно ровно до тех пор, пока тема меняет
   цвета и тени, но не размеры, — и за этим следит отдельный тест
   «темы не двигают раскладку»: он упадёт, если в теме появится размерный токен.

## Что делать, когда упало

**«768px, рельса 218: наезд по высоте на 146px — … header.thread-header»** — нашлась
новая беда. Идите по пути узла в исходники и чините вёрстку. Если чинить сейчас
нельзя — заведите запись в `известные.ts` с доводом, числом и адресом починки.

**«… не воспроизводится, удалите строку»** — беда из списка известных ПОЧИНИЛАСЬ.
Уберите строку из `ОТКЛОНЕНИЯ`. Это не придирка: без такого падения список за
полгода превратился бы в свалку, где живого не отличить от вымершего.

**«беда выросла, число в записи устарело»** — принимали 12 пикселей, стало 60.
Либо чините, либо переписывайте число и довод.

**«снимок не обновился — чинить src/test/…dump.tsx»** — снималка разметки перестала
делать этот снимок, а на диске лежит вчерашний. Стенд НЕ меряет протухший снимок:
он бы показал разметку, которой в продукте уже нет.

**«dist/assets исчез между сборкой и переносом шрифтов»** — в репозитории работает
вторая сессия, и её `vite build` очистил `dist`. Повторите прогон.

## Как добавить экран

Два шага, и первый — не здесь.

1. **Снять разметку.** В `src/test/*.dump.tsx` добавьте вызов, который рисует экран
   настоящим React и пишет `.dump/ИМЯ.html`. Там же задаётся ширина окна для
   `useMediaQuery` — от неё зависит, какую раскладку React выбрал.
2. **Записать экран** в `layout/экраны.ts`: имя снимка, каркас, диапазон ширин, на
   котором снимок честен, и файл снималки.

Каркасы: `место` — рельса слева и колонка `.lc-main` (в ней объявлен контейнер
`lc-workspace`, без него контейнерные запросы не работают вовсе); `страница` — экран
во всё окно (вход, «забыли пароль»); `рельса` — сам снимок и есть рельса.

⚠ **Диапазон обязателен и он не формальность.** Снимок снят при ОДНОЙ ширине окна, и
React в нём уже решил: рисовать карточку клиента оверлеем или колонкой, показывать
список или ленту. Мерить снимок вне диапазона — значит мерить состояние, которого у
человека не бывает.

## Про список известных отклонений

Механика двусторонняя, как у `PENDING` в `src/test/tokenContrast.test.ts`: запись
глушит беду, но падает, если беда исчезла или выросла. У каждой записи обязательны
довод, число и адрес починки — иначе это «мне лень», записанное в файл.

## Встраивание в выкатку

Сейчас проверка **не встроена** в `deploy/workstation/ship.sh`, и это осознанно:
ship гоняется на боевой сервер, прерывать его нельзя, а падение из-за незагруженного
браузера остановило бы выкатку у всей команды.

Что нужно, чтобы встроить:

* `npx playwright install --with-deps chromium` на машине, где идёт прогон
  (≈130 МБ в `~/Library/Caches/ms-playwright`, в Linux — ещё системные библиотеки);
* прогон **до** `ship.sh`, а не внутри него: сначала `npm run layout`, и только на
  зелёном — выкатка;
* в контейнере — `--no-sandbox` или свой пользователь: headless-shell под root в
  докере не стартует.

Риски, о которых надо знать заранее: прогон добавляет полторы минуты; он зависит от
`.dump/`, а тот в git не лежит и собирается снималкой заново; протухший снимок
превращает экран в пропуск, а не в падение (падает отдельный тест — читайте обе
строки итога).
