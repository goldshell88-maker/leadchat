## ОПРОВЕРГНУТО

### PERF-01 — механизм неверен, дефекта нет

Утверждение: «AppLayout перерисовывается на каждое сообщение → при открытой Статистике перерисовывается весь экран, потому что `route.Component` создаётся через `createElement` на каждом проходе».

Доказательства обратного:

1. `createElement(match.route.Component)` вызывается внутри `_renderMatches` (`node_modules/react-router/dist/index.js:602`, ветка `getChildren()`), а `_renderMatches` исполняется на уровне `RouterProvider`/`DataRoutes` (`index.js:1433`) — **не внутри AppLayout**. Пересборка цепочки outlet происходит только при смене состояния роутера (навигация, загрузка), а не при ререндере родителя.
2. Когда AppLayout перерисовывается от `useUnreadStore`/`useInboxStore` (AppLayout.tsx:202-203), `<Outlet/>` читает `RouteContext.outlet` из контекста. `useOutlet` возвращает `createElement(OutletContext.Provider, {value}, outlet)` — новый Provider, но **тот же самый объект-элемент `outlet`**. React делает bailout по `oldProps === newProps`, и поддерево страницы не перерисовывается.
3. Разницы между `element:` и `lazy → Component:` для ререндера родителя нет вообще — цитата из исходника react-router, на которую опирается находка, относится к ререндеру самого роутера.

График, тепловая карта и таблица менеджеров при входящем сообщении не перерисовываются. Остаётся только шапка+рельса — это несколько десятков узлов, не дефект.

### SHELL-11 — гонка есть, заявленного результата нет

Утверждение: «администратор вводит логин и оказывается в Чатах вместо /settings/team».

Опровержение — `LoginPage.tsx:85-86`:

```
await login(email.trim(), password, remember);
navigate(from, { replace: true });
```

`login()` ждёт `applySession()` целиком, включая `GET /auth/me` (sessionStore.ts:71-72). То есть **после** того, как права уже в сторе, handleSubmit делает ещё одну навигацию на `from`. Она работает и из размонтированного компонента: `activeRef` в `useNavigate` выставляется в `true` на mount и **никогда не сбрасывается** (`react-router/dist/index.js:213-216`, `896-899` — cleanup отсутствует), а `router.navigate` живёт на синглтоне. `from` — абсолютный путь, `fromRouteId` на разрешение не влияет.

Порядок: Navigate(/settings/team) → RequirePermission с пустыми правами → Navigate(/chats, replace) → приходит `/auth/me` → navigate(/settings/team, replace). Итоговый адрес правильный.

Реальный остаток: мигание экрана Чатов на ~100-200 мс и лишний круг запросов ChatsPage. Это cosmetic, а не minor, и формулировка «оказывается в Чатах, а не там, куда шёл» не воспроизводится.

### MODAL-05 — по сути опровергнуто

Три из четырёх утверждений не подтверждаются:

- «диалог ещё несколько секунд выглядит открытым» — **неверно**. У мутации есть оптимистичное обновление: `useConversationActions.ts:72-77`, `onMutate` немедленно пишет `{...old, status}` в `qk.conversations.detail(convId)`, который читает та же панель.

* Ловушка фокуса и Escape в модалках: проверил все 17 <Modal>/<Drawer> в src (HotkeysModal, InviteModal, OneTimeLinkModal, два окна TeamMembersTab, AccountsPage, ConnectChannelWizard, AssignOperatorsModal, TemplatesManager ×2, StepCard, SandboxDrawer, BlockClientButton ×2, InviteDialog, TransferDialog, UnloadQueueDialog, OutcomeModal, MyTodayWidget, ExportModal).
