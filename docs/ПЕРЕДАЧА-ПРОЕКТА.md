# Передача проекта

Документ для команды, которая принимает LeadChat и лид-бота: что это за система,
как она устроена, как её запускать, выкатывать и обслуживать, какие решения
приняты и что осталось сделать. Доступы к серверам, секреты и кабинеты сервисов
передаёт владелец отдельно, закрытым документом.

## Два репозитория

| Репозиторий | Что внутри |
|---|---|
| [leadchat](https://github.com/goldshell88-maker/leadchat) | платформа: бэкенд, веб-кабинет, настольное приложение, шлюз внешних API, выкатка, вся документация |
| [leadbot](https://github.com/goldshell88-maker/leadbot) | лид-бот: «мозг» диалога, Пульт оператора, панель, расширение Chrome для CRM, установка на Mac |

## Как устроено

```
Авито (вебхуки, API) ──► LeadChat: приём ──► PostgreSQL ──► WebSocket ──► веб-кабинет / настольное приложение
                              │
                              ├─► разбор телефона и адреса ──► шлюз внешних API ──► карты (DaData, Яндекс, OSM)
                              ├─► расшифровка голосовых (faster-whisper в воркере)
                              ├─► сводка диалога (бесплатные модели через шлюз)
                              └─► боты: свой движок сценариев и внешний лид-бот (через шлюз и мост)
```

- **Бэкенд** (`app/`): FastAPI, SQLAlchemy async, PostgreSQL (сообщения партиционированы по времени), Redis (очереди ARQ, pub/sub для WebSocket, блокировки).
- **Воркер** (`app/workers/`): приём и доставка сообщений, геокодинг, чтение адреса моделью, склейка клиентов, расшифровка голосовых.
- **Планировщик** (`app/scheduler/`): статистика, сторож каналов, дедлайны ботов, ремонт геокодинга и расшифровок, догон прогонов, пропущенных на перезапуске.
- **Веб-кабинет** (`frontend/`): React 18, Vite, Mantine; без Tailwind — токены `lc-vars.css`.
- **Настольное приложение** (`desktop/`): Tauri, Windows, автообновление.
- **Шлюз внешних API** (`gateway/`): отдельный сервис на второй машине; все походы к картам и моделям идут через него ([docs/46](46-ШЛЮЗ-API.md)). С основного сервера часть этих API недоступна — поэтому шлюз и лид-бот живут на второй машине, связанной с первой приватным мостом.
- **Лид-бот** (репозиторий `leadbot`): четыре слоя на каждый ход — правила, свой классификатор намерений, примеры из успешных диалогов, модель с плейбуком регламента. Связка с LeadChat — [docs/42](42-TZ-LEADBOT.md).

Архитектура и контракты — [DESIGN.md](../DESIGN.md), ТЗ — `docs/01…17`, решения и разборы — `docs/19…50`.

## Как начать

- Локальный запуск и команды — [README](../README.md) (десять минут: Docker, uv, Node).
- Тесты: `make test` (unit, SQLite + fakeredis), `make test-int` (PostgreSQL в testcontainers, нужен Docker), `uv run pytest gateway/tests`, во `frontend/` — `npm run test -- --run`, `npx tsc --noEmit`, `npm run lint`.
- Лид-бот: `cp config.example.json config.json`, `mac/setup-mac.command`, `mac/Start-bot.command`; быстрые тесты — `analysis/test_router_guards.py` и соседние (запускаются как скрипты).

## Выкатка и эксплуатация

- **LeadChat** выкатывается одной командой `deploy/workstation/ship.sh` с машины, у которой есть доступ к серверу: линтеры, типы и все наборы тестов → проверка секретов на сервере → дамп базы до миграций → сборка образов с меткой отката → миграции и перезапуск → строгая проверка боя снаружи (SM-1…16) → откат образов при провале. Порядок и аварийные случаи — [RUNBOOK-DEPLOY](RUNBOOK-DEPLOY.md), [05-DEPLOY-OPS](05-DEPLOY-OPS.md).
- **Лид-бот**: push в репозиторий выкатки на его сервере, затем там `git checkout` нужного коммита и перезапуск службы (хука нет — сам push код в бой не несёт).
- **Резервные копии**: база ночью и перед каждой выкаткой; копии шифруются (age) и уезжают на вторую машину и в облачное хранилище; раз в месяц — проверка восстановления. Ключ расшифровки у владельца.
- **Наблюдение**: сторож из нескольких проверок (очередь, приём, диск, сертификат, копии, лид-бот), проверка здоровья каждые 5 минут, самовосстановление службы бота.

## Правила, которые держит проект

- **LeadChat сам клиентам не пишет.** Автоматика только заполняет карточку (телефон, адрес, сводка); писать клиенту может только лид-бот — и он включается решением владельца.
- **Личные данные клиентов** не попадают в тесты, комментарии и документацию: там только вымышленные данные (телефоны `+7 900 111-22-4x/5x`). Во внешние модели текст уходит с маской телефонов; сводка диалога — только бесплатными моделями.
- **Продакшен — не git.** «Закоммичено» не значит «работает»: после выкатки новое проверяют грепом внутри контейнеров.
- **Выкатку не прерывают** и не правят файлы, пока она идёт.
- **Память бота — по аккаунтам** (требование владельца к следующему этапу): каждый аккаунт Авито для клиента — отдельный «мастер» со своим голосом, поэтому бот знает только то, что клиент сказал этому аккаунту; склеенная карточка клиента — инструмент операторов, а не память бота.

## Грабли, на которые уже наступали

- После `pg_restore` обязателен `ANALYZE`, иначе запросы идут минутами.
- JIT PostgreSQL на тяжёлых запросах компилировал дольше, чем работал.
- Интервальные задачи планировщика отсчитываются от старта, а планировщик перезапускается каждой выкаткой: такие задачи ставят с `start_date`.
- Задача ARQ под постоянным именем без `keep_result=0` молча не ставится повторно.
- Авито держит на аккаунт ровно одну подписку на вебхук.
- Кириллица в значении HTTP-заголовка роняет `new Headers()` в браузере.
- Сторож по тексту исходника может зеленеть и без самой проверки: каждый сторож доказывают «диверсией» — снимают защищаемое и видят красный тест.
- Разбор адреса по форме города: в Ангарске номера до 33 — микрорайоны, выше — кварталы; в Нефтеюганске — микрорайоны; в Набережных Челнах — комплексы; в Зеленограде — корпуса.

## Открытые задачи

- **Карта не отдаёт населённый пункт и район** в ответе шлюза — поэтому деревня в районе может подписываться городом объявления, а посёлок внутри города не находится как место. Нужно поле района/пункта в договоре шлюза.
- **Лид-бот**: связка с найденными адресами и расшифровками голосовых, обучение по диалогам лучших сотрудников с проверкой моделью-судьёй, «живой» тон без обмана клиентов; включение — решением владельца.
- **Кириллические имена в коде** переводятся на английские модуль за модулем (новый код — сразу на английском).
- **React Router 7**: переход упирается в поведение ленивых маршрутов.
- **Выпуск настольного приложения**: секреты подписи в окружении GitHub `desktop-release`.
