# 11 — Каталог экранов: макеты и UX-спецификация

Документ детализирует базовые макеты DESIGN §3 до уровня «можно верстать»: для каждого экрана —
ASCII-макет, аннотации элементов, состояния (скелетон / пусто / ошибка) и ролевые отличия.
Контракты не переопределяются: endpoints и WS-события — 01-API-SPEC, права — 01 §12
(проекция DESIGN §5.1), шаги ботов — 02 §1, метрики — 06, десктоп-слой — 04, компонентные
имена — 03 §1.2. Токены темы, компоненты и типографика — docs/10-UX-DESIGN-SYSTEM.md.
Карта «экран → спринт» — 09 §3.

---

## 0. Соглашения документа

**Роли** обозначаются буквами: **A** — admin, **H** — head (руководитель), **M** — manager,
**O** — observer. UI строится по `permissions` из `GET /auth/me` (03 §5.1), роль в скобках —
для читаемости.

**Палитра** (фирменный стиль Lead Partner, светлая тема — основная):
primary `#3cc13b`, hover `#2ea32d`, subtle-фон `#d8f3d8`, focus ring `rgba(60,193,59,.25)`;
текст — трёхуровневая шкала из 10 §1.3: основной `#212529` (text-1), вторичный `#495057`
(text-2), третичный `#6c757d` (text-3, время/плейсхолдеры); границы `#dee2e6`, поверхности `#f8f9fa`/`#ffffff`;
danger `#dc3545`, warning `#ffc107`, info `#0dcaf0`. Тёмная тема — опция (переключатель
в профиле, 03 §8 + правка 09 §2.6). В макетах цвет указывается аннотацией, не рисунком.

**Каждый экран описывается в четырёх состояниях**:

| Состояние | Правило по умолчанию (если у экрана не оговорено иное) |
|---|---|
| Загрузка | Скелетоны формы будущего контента (не спиннер по центру); повторные заходы — мгновенно из кэша TanStack Query + фоновая ревалидация |
| Пусто | Иллюстративная иконка + 1 фраза + (если у роли есть право) CTA-кнопка; тексты — §8.2 |
| Ошибка | Плашка в зоне контента: «Не удалось загрузить. [Повторить]»; сетевые ретраи — молча, кнопка — для ручного повтора |
| Норма | Основной макет |

**Хоткеи** — единый реестр 10 §5.1 (Enter/Shift+Enter, `/`, `Ctrl+K` — фокус в поиск,
`J`/`K` или `↓`/`↑` — по списку, `Alt+↓/↑` — следующий/предыдущий с непрочитанными,
`Alt+1..4` — вкладки, `Ctrl+Shift+N` — заметка, `Esc`, `Ctrl+Shift+L`); карта по
спринтам — 09 §1.0. Здесь упоминаются в местах применения, дубли реестра не заводим.

**ASCII-обозначения**: `[Кнопка]`, `[поле____]`, `(•)`/`( )` — radio, `[x]`/`[ ]` — чекбокс,
`▾` — селект/раскрытие, `●` — бейдж/индикатор, `⋮` — меню строки. Ширина макетов ≈ 100 колонок,
это схема пропорций, не пиксельная сетка.

### 1.2. Аннотации

- Карточка 400 px, вертикально по центру; фокус при загрузке — в Email; Enter в любом поле
  сабмитит форму. Ссылка «Скачать…» → `/download` (§4.4), ссылка на сайт — новая вкладка.
- «Запомнить меня» → `remember: true` в `POST /auth/login` (01 §2.1): refresh-cookie 14 дней;
  без галки — session-cookie.
- При старте приложения до показа формы идёт тихий `POST /auth/refresh` (03 §6 «Логин»):
  если cookie жива, пользователь `/login` не видит вовсе — сразу `/chats`.
- Кнопка «Войти» при сабмите: disabled + спиннер внутри кнопки (форма не блокируется скелетоном).

### 1.3. Состояния

| Состояние | Вид |
|---|---|
| Загрузка (bootstrap) | Полноэкранный `FullscreenLoader` c логотипом — пока идёт тихий refresh; формы не видно, мигания «логин → кабинет» нет |
| Неверный пароль (`401 invalid_credentials`) | Под формой красная строка «Неверный email или пароль» (текст един для несуществующего email и неверного пароля — не раскрываем, какой именно); поля подсвечены danger; пароль очищается, фокус в него; лёгкий shake-анимацией карточки |
| Блокировка (`403 account_locked`) | Форма disabled целиком, плашка warning: «Слишком много попыток входа. Повторите через 14:59» — таймер обратного отсчёта из `details.retry_after_sec`, по нулю форма разблокируется сама. Блокировка наступает после 10 неудачных попыток (по IP и по учётке, DESIGN §9) |
| Учётка отключена (`403 forbidden`) | Плашка danger: «Учётная запись отключена, обратитесь к администратору» (текст из API) |
| Сеть недоступна | Плашка «Сервер недоступен. Проверьте соединение. [Повторить]» |

скелетон карточки.

│  [__________________] [👁]  │          │                              │
│  ▓▓▓▓▓▓░░░░  надёжный       │ ← шкала  │  [ Перейти ко входу ]        │
│  Повторите пароль            │          └──────────────────────────────┘

│                              │
│  [  Сохранить и войти  ]     │

- Имя и email — из ответа `GET /auth/invite/{token}`, email readonly.
- Клиентская валидация: длина ≥ 10 (лимит API), совпадение полей; шкала надёжности —
  подсказка, не блокер.
- `POST /auth/invite/accept` → тело как у login: пользователь **сразу залогинен** и попадает
  в `/chats` (для M — на вкладку «Мои»). Ошибки: `404 invite_expired` — правый макет;
  `400 validation_error` — подсветка поля.
- Токен одноразовый (TTL 72 ч): повторное открытие использованной ссылки — тот же экран 404.

### 2.1. Левая колонка — список диалогов

**Строка диалога** (высота фиксированная 76 px, measure выключен — 09 §2.5; то же
значение 76px/3 ряда зафиксировано в 10 §3.3):

```
┌──────────────────────────────────────────┐
│ ⚑🤖 Имя клиента              (негатив) 12:40 │  ряд 1: значки состояния · имя · чип · время
│ Название объявления · LP-Москва          │  ряд 2: item_title · account.title (#6c757d)
│ ✓ Вы: «Добрый день! Замена…»          2● │  ряд 3: последнее сообщение · бейдж непрочитанных
└──────────────────────────────────────────┘
```

| Индикатор | Условие (поле из 01 §5.1) | Вид |
|---|---|---|
| `2●` | `unread_count > 0` | зелёный бейдж-кружок справа, число; строка — полужирное имя |
| `⚑` | `transferred_to_me: true` | оранжевый флажок перед именем; гаснет после открытия диалога |
| `🤖` | `bot_active: true` | серый значок перед именем; тултип «Диалог ведёт бот» |
| `(негатив)` | `"негатив" ∈ tags` | чип danger `#dc3545` (светлый фон, красный текст); прочие теги в строке не показываются (место), полный список — в карточке |
| Префикс «Вы:» / «Бот:» / имя коллеги | `last_message.direction = out` | у исходящих; статус ✓/⏳/✗ последнего исходящего — миниатюрой перед текстом |
| Точка статуса | `status` | цвет полоски слева от аватара: new — синий info, in_progress — зелёный, closed — серый |

Сортировка — серверная, фиксированная (01 §5.1): сначала непрочитанные (внутри них диалоги
с тегом «негатив» — первыми), затем по `last_message_at DESC`. Новые события приходят по WS
(`message:new` с `conversation_patch`) — строка обновляется и пересортировывается без запроса;
звук — для входящих (кроме открытого диалога в фокусе).

**Вкладки-фильтры** `[Мои 7|Все|Новые 3|Закрытые]` → `?tab=` (01 §5.1). Счётчики на вкладках
«Мои» и «Новые» — количество диалогов с непрочитанными в этих выборках (клиентский подсчёт
из unreadStore). Вкладка по умолчанию: M — «Мои», остальные — «Все». `J`/`K` (или `↓`/`↑`) —
следующий/предыдущий диалог, `Alt+↓`/`Alt+↑` — следующий/предыдущий с непрочитанным
(реестр 10 §5.1).

**Поиск** `[🔍 Поиск…]` — `Ctrl+K` фокусирует из любого места `/chats` (см. §8.4). Debounce
300 мс → `GET /conversations?q=` — ищет по имени, нормализованному телефону и полнотексту
сообщений (FTS, русская морфология). Во время поиска вкладки затемняются (поиск идёт по всем
диалогам), под полем — строка «Найдено: 14 · [Сбросить ✕]» (`Esc` очищает).

**Фильтры-селекты**: «Аккаунт ▾» (все роли; список из `GET /avito-accounts` для A/H, для
M/O — из значений, встреченных в диалогах, без отдельного endpoint'а — поле `account` есть в
каждой строке списка); «Менеджер ▾» — только A/H (03 §5.2), см. §2.5.2.

**Состояния колонки**:

- *Скелетон*: 8 строк-плейсхолдеров (аватар-круг + две серые полосы), вкладки активны.
- *Пусто*: по вкладкам — тексты §8.2; для вкладки «Новые» — позитивный тон
  («Новых диалогов нет — всё разобрано 👍»).
- *Ошибка*: плашка со «[Повторить]» на месте списка; вкладки и поиск остаются.
- *Догрузка* (infinite scroll): 3 скелетон-строки внизу.

### 2.2. Центр — лента переписки

**Шапка**: имя клиента · объявление (тултип с полным названием) · «аккаунт: LP-Москва» ·
статус-селект (право `conversations:manage`; для O — статичный бейдж). На мобильном —
кнопка «← назад» (03 §8.2). Если бот активен — синяя полоска под шапкой:
«🤖 Диалог ведёт бот — ваше сообщение отключит его» (для ролей с `messages:send`).

**Пять типов пузырей** (все — компонент `MessageBubble`/`NoteBubble`, 03 §1.2):

```
1. Входящий (client, слева, фон gray-1):     2. Исходящий (operator, справа, фон #d8f3d8):
┌────────────────────────┐                       ┌─────────────────────────────┐
│ Здравствуйте! Экран    │                       │ Добрый день! Замена экрана  │
│ разбит, почём?         │                       │ iPhone 13 — от 8 900 ₽      │
└────────────────────────┘                       │            Анна С. · 12:41 ✓│
  12:40                                          └─────────────────────────────┘

3. Бот (справа, фон #eef9ee, dashed-рамка #9ee09d, значок 🤖):  4. Заметка (по центру/на всю ширину, жёлтый):
┌─────────────────────────────┐              ╔═════════════════════════════════════╗
│ 🤖 Мастер ответит утром.    │              ║ 🗒 торгуется, дать скидку до 10%    ║
│ Оставьте телефон ✔          │              ║ Анна С. · 12:45 · видно только      ║
│                  Бот · 22:03│              ║ сотрудникам                         ║
└─────────────────────────────┘              ╚═════════════════════════════════════╝
                                              (фон #fff8dc, текст #7a6400 — 03 §8.1)
5. Системное (по центру, серым, без пузыря):
        ─ Диалог передан: Анна Смирнова → Глеб Беляков.
          Комментарий: торгуется, дай скидку до 10% ─
```

- Имя оператора у исходящих показывается всегда (менеджеров несколько; `sender.full_name`).
- Вложения: изображения — превью с резервом высоты по aspect ratio (09 §2.5), pdf — карточка
  «📄 имя · размер»; клик — просмотр по подписанной ссылке (протухла — фронт перезапрашивает
  деталь, 01 §6.1).
- **Разделители дат**: «Сегодня», «Вчера», далее «28 июля» (`DateDivider`).
- **«Клиент вернулся»**: чип в стиле системного сообщения
  `─ ↩ Клиент вернулся — диалог переоткрыт ─`. Рендерится фронтом: в realtime — по
  `conversation:updated` со сменой `closed → new` при новом входящем; при холодной загрузке —
  перед первым входящим, следующим за заметкой бота «Диалог закрыт ботом…». Чисто
  презентационный элемент, новых полей API не требует; для ручных закрытий без следа в ленте
  чип показывается только в realtime — осознанный компромисс.
- **Статусы доставки** исходящих: `⏳` pending (серый) → `✓` delivered → `✗` failed
  (danger) + под пузырём строка «Не доставлено: Авито: чат недоступен · [Повторить]»
  (текст из `message:status.error`; кнопка — `POST /messages/{id}/retry`, право
  `messages:send`; у H/O кнопки нет).
- «↓ новые сообщения» — floating-кнопка, если скролл не внизу и пришло новое.
- Индикатор «печатает»: под шапкой мелко «Иван печатает…» (клиент, best-effort) или
  «Анна печатает…» (коллега в этом же диалоге) — гаснет через 5 с (01 §11.3 typing).

**Состояния центра**:

- *Диалог не выбран*: `EmptyThreadPlaceholder` — крупная иконка 💬, «Выберите диалог слева
  или нажмите Ctrl+K для поиска».
- *Скелетон*: 5–6 пузырей-плейсхолдеров попеременно слева/справа.
- *Пустая лента* (диалог есть, сообщений нет — редкий случай backfill): «Сообщений пока нет».
- *Ошибка/404*: нотификация «Диалог не найден» + возврат к списку (03 §6 deep-link).
- *Прокрутка вверх*: догрузка истории курсором, 3 скелетон-пузыря сверху; в офлайне десктопа
  глубже кэша — плашка «история доступна при подключении» (04 §5.4).

### 2.3. Панель ввода (Composer)

```
[⚡ шаблоны]  [📎]  [🗒 заметка]                                ← ComposerToolbar
┌──────────────────────────────────────────────────────────────┐
│ Написать сообщение…                                     [➤] │  ← режим «сообщение», фон #fff
└──────────────────────────────────────────────────────────────┘
   Enter — отправить · Shift+Enter — перенос строки

Режим «заметка» (toggle 🗒 или из пикера):
┌──────────────────────────────────────────────────────────────┐
│ 🗒 Заметка — увидят только сотрудники                   [➤] │  ← фон #fff8dc, рамка #ffc107
└──────────────────────────────────────────────────────────────┘
```

- `/` в **пустом** поле — открыть пикер быстрых ответов (§3.1); `⚡` — то же кнопкой.
- `📎` — файл-пикер: до 5 вложений, ≤ 20 МБ, jpeg/png/webp/pdf (01 §6.5); выбранные — чипы
  над полем с превью и ✕; загрузка сразу (`POST /media`), прогресс на чипе.
- Черновики — по диалогу (`chatUiStore.drafts`), переключение диалогов текст не теряет.
- Отправка оптимистична: пузырь появляется мгновенно с ⏳ (03 §3.4); в десктопе путь всегда
  через outbox (04 §5.3).
- Ошибки по контракту 01 §6.2: `422 conversation_closed` — вместо поля ввода плашка
  «Диалог закрыт. [Вернуть в работу]» (PATCH status → in_progress, назначается на меня);
  `409 account_needs_reauth` — плашка danger «Аккаунт Авито отключён — отправка невозможна»
  (+ для A ссылка «Переподключить → /settings/accounts»); `413` — счётчик символов
  краснеет после 4000 (счётчик виден с 3500).
- Лимит Авито ~1000 символов на сообщение: воркер сам режет длинные тексты — UI не блокирует,
  но после 900 символов показывает подсказку «Длинное сообщение придёт клиенту частями».

2. **ОБЪЯВЛЕНИЕ**: превью-фото, `item_title`, `item_price`, «Открыть на Авито ↗»

### 2.5. Четыре ролевых варианта

Ролевые различия — режимы одного экрана (09 §3), сведены к трём зонам: композер, карточка,
фильтры.

#### 2.5.1. Менеджер (M) — полный рабочий вариант

Макет §2.0 целиком. Особенности: вкладка по умолчанию «Мои»; виджет «моя статистика за
сегодня» в подвале левой колонки (§6.3); свободного селекта «ответственный» нет — передача
только через «→ Передать»; фильтра «Менеджер ▾» нет; пункта 📊 в NAV нет.

#### 2.5.2. Руководитель (H) — режим просмотра

```
Центр, низ панели (вместо композера сообщений):
╭──────────────────────────────────────────────────────────────╮
│ 👁 Режим просмотра — назначьте менеджера или передайте диалог │ ← ReadOnlyBanner, фон info
╰──────────────────────────────────────────────────────────────╯
┌──────────────────────────────────────────────────────────────┐
│ 🗒 Заметка — увидят только сотрудники                   [➤] │ ← композер только-заметки
└──────────────────────────────────────────────────────────────┘   (⚡ и 📎 скрыты, 03 §5.3)
```

- Отправка сообщений недоступна (`messages:send` ❌; бэкенд ответит `403 read_only_role`) —
  UI поле сообщений не показывает вовсе, композер закреплён в режиме заметки (жёлтый).
- Доступно: заметки, смена статуса, свободный селект «Ответственный ▾» в карточке,
  «→ Передать» (переназначение — основной инструмент H).
- В левой колонке дополнительно фильтр «Менеджер ▾» (в т.ч. пункт «Без ответственного» и
  деактивированные сотрудники — чтобы находить осиротевшие диалоги, 01 §3.5).
- Кнопки «Повторить» у ✗-сообщений нет; пикера шаблонов нет.
- NAV: есть 📊; ⚙️ — общие шаблоны, аудит, профиль.

#### 2.5.3. Наблюдатель (O) — чистое чтение

- Композера нет совсем (ни поля, ни плашки — просто лента до низа; 03 §5.3).
- Лента **без жёлтых заметок** — бэкенд не отдаёт `direction=note` наблюдателю (01 §6.1);
  системные сообщения о передачах видны.
- Карточка: секции КЛИЕНТ / ОБЪЯВЛЕНИЕ / ТЕГИ / ИСТОРИЯ; секций ДИАЛОГ (управление) и
  ЗАМЕТКИ нет; статус в шапке — статичный бейдж.
- Фильтры и поиск — полноценные (роль для стажёров и контроля качества, DESIGN §5.2);
  фильтра «Менеджер ▾» нет (привязан к `stats:all`, 03 §5.2).
- NAV: только 💬 и ⚙️ (внутри — лишь профиль без личных шаблонов).

#### 2.5.4. Админ (A)

Как M (полный композер и отправка) **плюс**: свободный селект «Ответственный ▾», фильтр
«Менеджер ▾», NAV полный (📊 и все разделы ⚙️). Виджет «моя статистика» админу не показывается
(03 §5.2) — его место в подвале колонки занимает счётчик «Всего диалогов: 120».

## 3. Быстрые ответы <a id="templates"></a>

### 3.1. Попап-пикер в чате (`TemplatePickerPopover`)

Открытие: `⚡` или `/` в пустом поле (фокус сразу в поиске). Доступен ролям с
`messages:send` (A, M) — у H/O не показывается.

```
┌─ Быстрые ответы ────────────────────────────────┐
│ [🔍 найти шаблон…__________________]            │
│─────────────────────────────────────────────────│
│ ОБЩИЕ · Приветствия                             │
│ ▸ Приветствие      Здравствуйте, {имя}! Это…    │ ← активная строка: фон #d8f3d8
│ ▸ Приветствие-ночь Мастер ответит утром…        │
│ ОБЩИЕ · Цены                                    │
│ ▸ Диагностика      Диагностика бесплатная при…  │
│ МОИ                                             │
│ ▸ Моя скидка       Могу предложить скидку 5%…   │
│─────────────────────────────────────────────────│
│ ↑↓ — выбрать · Enter — вставить · Esc — закрыть │
│                      [⚙ Управлять шаблонами]    │
└─────────────────────────────────────────────────┘
```

- Данные: `GET /templates?scope=all` (личные + общие), группировка по области и папке.
  Поиск — по title/body локально по загруженному списку (список короткий), серверный `q` —
  запасной путь при > 200 шаблонов.
- Enter/клик — вставка `body` в поле ввода **с подстановкой переменных на фронте**
  (01 §7): `{имя}` → имя клиента, `{менеджер}` → моё имя, `{объявление}` → item_title.
  Непроставляемая переменная (нет имени клиента) остаётся плейсхолдером и выделяется в поле —
  оператор видит, что надо дописать. Курсор — в конец, попап закрывается, фокус в поле.
- Набор текста после `/` фильтрует список на лету (`/дост` → шаблоны про доставку).
- «⚙ Управлять шаблонами» → M: личные в `/settings/profile`; A/H: `/settings/templates`.
- *Пусто*: «Шаблонов пока нет. [Создать первый]» (ведёт туда же). *Ошибка*: строка с
  «[Повторить]» внутри попапа.

Модалка создания/редактирования: Название · Текст (textarea со счётчиком и кнопкой `{…}` —

увидит вся команда»; ошибка — стандарт.

### 3.3. Личные шаблоны (все, кроме O)

переключателя «Общий». M попадает сюда из пикера («⚙ Управлять»). O блока не видит
(`templates:own` ❌ — ему нечем отвечать).

## 4. Настройки <a id="settings"></a>

Общий каркас `/settings/*`: вторая NAV-колонка «Аккаунты Авито (A) · Команда (A; H — только

### 4.1. Аккаунты Авито — `/settings/accounts` (A; H — просмотр без кнопок, 01 §4) <a id="accounts"></a>

```
┌─ Настройки · Аккаунты Авито ──────────────────────────────────────────────┐
│                                              [+ Подключить аккаунт Авито] │
│ ┌──────────────────────────────┐  ┌──────────────────────────────┐        │

│ │ Webhook: ✅ ok · 09:58       │  │ Токен отозван на стороне     │        │
│ │ Бот: [Первичный приём ▾]     │  │ Авито. Приём сообщений       │        │
│ │ Подключён 02.06.2026         │  │ остановлен.                  │        │
│ │                              │  │                              │        │
│ │ [Проверить вебхук] [Откл.]   │  │ [   🔄 Переподключить   ]    │ ← CTA  │
│ └──────────────────────────────┘  └──────────────────────────────┘        │
│ ┌──────────────────────────────┐                                          │
│ │ LP-Архив               ⚪    │   ⚪ disabled: серые карточка и текст,   │
│ │ Отключён вручную. История    │      кнопка [Включить]                   │

│ └──────────────────────────────┘                                          │
└───────────────────────────────────────────────────────────────────────────┘
```

- Статусы (01 §4.1): 🟢 `active` · 🔴 `needs_reauth` (карточка с danger-рамкой, CTA
  «Переподключить» — главный элемент) · ⚪ `disabled`.
- Webhook-строка: ✅ ok / ❌ failed / ⏳ not_registered + время `last_event_at`; если событий
  нет > 15 мин при живой реконсиляции — иконка ⚠ с тултипом «Вебхук молчит — сообщения
  доезжают реконсиляцией с задержкой» (01 §4.1). «[Проверить вебхук]» →
  `POST .../webhook/check`, результат — обновлённая строка + тост.
- Селект «Бот» → `PATCH /avito-accounts/{id}` (`bot_id`); привязка выключенного бота —
  предупреждение из `details.warning: bot_disabled`.
- «Отключить» — конфирм «Приём сообщений остановится; история останется читаемой».

**OAuth-флоу глазами админа** («Подключить» и «Переподключить» — один сценарий, 01 §4.2–4.4):

```
1. Клик [+ Подключить аккаунт Авито]
   → GET /avito/connect-url → браузер уходит на avito.ru/oauth (текущая вкладка)
2. Страница согласия Авито: «LeadChat запрашивает доступ к сообщениям…» → [Разрешить]
   (админ должен быть залогинен на Авито под НУЖНЫМ аккаунтом — подсказка в конфирме
    перед редиректом: «Убедитесь, что вы вошли на Авито под подключаемым аккаунтом»)
3. Возврат на /settings/accounts:
   ?connected=1      → тост success «Аккаунт подключён. Загружаем историю чатов…»
                       + карточка появляется со статусом 🟢; по завершении backfill
                       придёт WS notify: «История загружена: 1 214 диалогов»
   ?error=oauth_failed     → тост danger «Не удалось подключить аккаунт. Попробуйте ещё раз»
   ?error=account_mismatch → тост danger «Вы авторизовали другой аккаунт Авито —
                             переподключение отменено» (только для Переподключить)
```

Реактивный путь: событие `account:needs_reauth` (только admin-сессиям) → красный бейдж на ⚙️
в NAV и тост «Аккаунт „LP-Москва" требует переподключения» (в десктопе — системный тост,
клик ведёт сюда).

*Состояния*: скелетон — 2 карточки-плейсхолдера; пусто — онбординг-заглушка «Подключите
первый аккаунт Авито, и диалоги появятся в „Чатах" через минуту» + большая CTA; ошибка —
стандарт. Для H: карточки без кнопок и селекта бота (read-only, право `accounts:read`).

### 5.2. Редактор сценария — вертикальный список карточек-шагов

```

│ │ 🔀 check_hours    condition: рабочее время? → handoff_day     │  ↑ ↓  ▸     │
│ │ 👤 handoff_day    handoff · «Клиент описал проблему…»    ⛔   │  ← с ошибкой│

Общее для карточки шага (02 §5.1): иконка типа, `id` (моноширинный, редактируемый — все
ссылки на шаг обновляются на клиенте), сводка в одну строку; разворот `▾` — форма. Смена типа
(Select) сбрасывает `params` — конфирм. Все переходы — Select со списком `id` шагов;
у nullable-ссылок первый пункт «— дефолт: передать оператору —». Текстовые поля — с кнопкой
`{…}`: системные `{client_name}` `{item_title}` `{item_price}` `{account_title}` + переменные
`ask`-шагов выше по списку. Перестановка — стрелками ↑↓.

**Формы всех девяти типов шагов** (поля = params из 02 §1.3):

| Тип | Поля формы |
|---|---|
| 💬 `send` | Текст (textarea 1–1000, `{…}`) · далее → [шаг] |
| ❓ `ask` | Вопрос (опционален — «уже задан предыдущим send») · Переменная (`^[a-z][a-z0-9_]{0,31}$`, латиница, подсказка при кириллице) · Валидатор [любой ответ / телефон / число / regex…] (regex — доп. поле с live-проверкой компиляции) · Retry-текст · Попыток [1–5] · Таймаут [30м/1ч/2ч/12ч/24ч/3д/без лимита — с ⚠ «бот может ждать вечно»] · ответ → · по таймауту → · попытки исчерпаны → |
| 📋 `menu` | Текст вопроса · Переменная (опц.) · таблица вариантов: label · ключевые слова через запятую · переход → · [+ вариант] (1–10) · Retry-текст · Попыток · Таймаут · мимо вариантов → · по таймауту → |
| 🔀 `condition` | Строки «если [вид ▾: рабочее время (от/до/часовой пояс/дни; интервал через полночь подсвечивается подсказкой «через полночь») / переменная существует (var) / переменная равна (var, value) / текст содержит (keywords) / текст по regex] → [шаг]» · [+ условие] (1–10) · обязательное «иначе → [шаг]» |
| ✨ `ai_answer` | Порог уверенности — слайдер 0–1 шаг 0.05 (подпись «ниже порога → передать оператору») · Макс. длина ответа [100–1000] · Глубина контекста [2–30 сообщений] · далее → · при низкой уверенности → |
| 👤 `handoff` | Причина (строка, default `scenario`) · Комментарий менеджеру (попадёт заметкой в диалог) · Теги (TagsInput). Терминальный — переходов нет, бейдж «завершает сценарий» |
| ✅ `close` | Прощальное сообщение (опц.) · [x] Закрыть молча. Терминальный |
| 🏷 `tag` | Теги (TagsInput, ≤50 симв.) · далее → |
| 🗒 `note` | Текст заметки (`{…}`; видна только сотрудникам) · далее → |

Черновик живёт в Zustand-сторе, на сервер уходит только по «Сохранить» (02 §5.1); уход со
страницы с несохранённым — конфирм «Изменения не сохранены».

### 5.3. Валидация

Живая (на вводе, JSON Schema-слой) + полная при «Сохранить» (семантика графа, коды 02 §5.2).
Ошибки `⛔` — красная рамка карточки + список под панелью действий; «Сохранить» disabled.
Предупреждения `⚠` — жёлтая рамка; кнопка меняется на «Сохранить с предупреждениями».
Клик по строке списка — скролл к шагу и его раскрытие. Серверный `422` (истина) рендерится
в тот же список по `{step_id, field, code, message}`.

- Работает с **черновиком** (сохранять не нужно); старт — `POST /bots/sandbox/start`, `422`
  с ошибками валидации рендерится списком §5.3 поверх Drawer («сначала почините сценарий»).
- Лента: сообщения «клиента» справа, бота — слева; серые строки — трассировка шагов
  (`kind: step/waiting/ai_call`), жёлтые — заметки, красная плашка — handoff с причиной,
  серая плашка «✅ диалог закрыт» — close.

стандарт; 404 — «Бот не найден» + возврат к списку.

### 6.2. Аннотации

- **Карточки** (`GET /stats/summary`, состав — 06 §4.1): дельта к прошлому периоду той же
  длины; стрелка и цвет — семантические: для времени ответа снижение — зелёное («быстрее»),
  для остальных рост — зелёный. Snapshot-карточки («В работе», «Ждут ответа») — без дельты
  (сравнивать не с чем, `delta_pct: null`); «Ждут ответа» > 0 — акцент warning. Карточка FRT
  раскрывается тултипом: медиана/среднее, астрономическое/рабочее время, отвечено/без ответа.
  «Закрыто ботом» — тултип «54 из 290»; «Телефонов» — разбивка по источникам (бот/regex/
  вручную).
- **График** (`GET /stats/timeseries`): селект метрики (6 значений enum), «по часам» доступно
  при периоде ≤ 7 дней (иначе disabled с тултипом). Пустые дни — 0; для FRT-медианы «нет
  данных» — разрыв линии (`null`), не ноль.
- **Тепловая карта** (`GET /stats/heatmap`): 7×24, интенсивность — шкала от `#d8f3d8` к
  `#2ea32d`; tooltip «Вт 14:00 — 37 входящих»; подпись «видно, когда нужен дежурный».
  Фильтр по менеджеру на неё не действует (входящие менеджеру не принадлежат) — при активном
  фильтре над картой бейдж «все менеджеры».
- **Таблица менеджеров** (`GET /stats/managers`): сортировка по клику на заголовок
  (server-side, параметры `sort`/`order`), деактивированные сотрудники — серым с пометкой;
  строка «Итого» считается бэкендом по всей выборке (медиана суммы ≠ сумма медиан — 06 §4.4).
  Клик по строке — фильтрует весь экран по менеджеру.

→ 202: тост-прогресс «Готовим выгрузку…» (спиннер; поллинг GET /stats/export/{job_id} раз в 2 с)
→ done:   тост success «Выгрузка готова · [Скачать leadchat-stats_…xlsx]» (ссылка живёт 24 ч)
→ failed: тост danger с текстом ошибки («Больше 100 000 диалогов — сузьте период»)
Ошибки сразу: 409 «Предыдущий экспорт ещё готовится», 429 «Лимит выгрузок на сегодня исчерпан»
```

CSV — только лист «Диалоги» (06 §5.2): при выборе CSV чекбоксы листов заменяются подписью.

### 6.4. Виджет «моя статистика» менеджера (где живёт)

Роль M (`stats:own`; экрана `/stats` у M нет). Живёт **в подвале левой колонки `/chats`**
(§2.0, зона под виртуальным списком) — компактная строка + поповер:

```
Подвал колонки (всегда виден):        Поповер по клику:
┌───────────────────────────────┐    ┌─ Моя статистика за сегодня ─────────┐
│ Сегодня: 5 взято · 3 закрыто  │    │ В работе сейчас                7    │
│ FRT 1м14с · ⚠ 2 ждут ответа   │    │ ⚠ Ждут моего ответа            2    │
└───────────────────────────────┘    │ Взято сегодня                  5    │
  «ждут ответа» — warning-акцент,    │ Закрыто сегодня                3    │
  0 → фраза скрыта                   │ Отправлено сообщений          64    │
                                     │ Первый ответ (медиана)     1м14с    │
                                     │ Отвечено диалогов              6    │
                                     └─────────────────────────────────────┘
```

Данные — `GET /stats/my/today` (06 §6): загрузка при старте рабочего места + обновление раз
в 60 с и по фокусу окна (серверный кэш 30 с делает это дёшево). Цифры сходятся с `/stats`
руководителя цифра в цифру (06 §6.2). На мобильной раскладке — пункт в меню аватара.

*Состояния `/stats`*: скелетон — 8 серых карточек + прямоугольники графика/карты/таблицы;
пусто (нет данных за период) — карточки с «0»/«—», под графиком «Нет данных за выбранный
период»; ошибка — стандартная плашка на весь экран контента с «[Повторить]».

## 7. Десктоп-специфика (Tauri) <a id="desktop"></a>

### 7.1. Трей-меню (04 §3.1)

```
┌──────────────────────────────┐
│ ● На месте                   │ ← radio-группа presence; синхронна с UI (PUT /presence)
│ ○ Отошёл                     │

│ Новые чаты: 3                │ ← disabled-строка, живой счётчик
├──────────────────────────────┤
│ Развернуть LeadChat          │ ← = ЛКМ по иконке = Ctrl+Shift+L
├──────────────────────────────┤
│ Выход                        │ ← единственный способ закрыть процесс

```

Иконка трея — с красным бейджем числа непрочитанных (готовые PNG `tray_0…9plus`); tooltip
«LeadChat — новых: 3». Крестик окна сворачивает в трей (первый раз — тост «LeadChat
продолжает работать в трее»); бейдж дублируется оверлеем на кнопке таскбара.

### 7.2. Тост Windows с «Ответить» (04 §4)

```
┌─ LeadChat ────────────────────────────────┐
│ Иван Петров · Ремонт iPhone 13            │
│ А сколько будет стоить замена экрана?     │
│ LP-Москва                                 │
│ [Быстрый ответ…____________] [Ответить]   │
│                              [Открыть]    │
└───────────────────────────────────────────┘
```

- Показывается по матрице 04 §4.1 (только когда окно скрыто/не в фокусе; сообщения бота —
  не тостятся; «диалог передан вам» — тост всегда, приоритетный).
- «Ответить» — отправка прямо из тоста через outbox (работает даже без сети); «Открыть»/клик
  по телу — фокус приложения на `/chats/{id}`, курсор в поле ввода.
- Поток сообщений троттлится: > 3 тостов за 10 с → сводный «12 новых сообщений в 5 диалогах»
  (04 §4.3). Тосты у H/O тоже работают (события чтения), но без кнопки «Ответить» — только
  «Открыть».

### 7.3. Индикатор офлайна и очереди ⏳ в шапке

В правом углу верхней панели приложения (рядом с аватаром):

```
онлайн:  (пусто — норма не индицируется)
офлайн:  [⚡ офлайн · в очереди 2 ⏳]   ← чип warning #ffc107, тултип:
                                        «Сообщения отправятся при появлении сети»
flush:   [⟳ отправляем очередь… 1/2]   ← на время outbox_flush
```

Сообщения из очереди в ленте помечены ⏳; ошибка после ретраев — ✗ с «[Повторить]/[Удалить]»
(04 §5.3). Чтение в офлайне — из SQLite-кэша (200 диалогов × 100 сообщений); вместо картинок —
плейсхолдер «доступно при подключении». Веб-версия очереди не имеет: там композер в офлайне
блокируется плашкой «нет соединения» (09 §4).

### 7.4. Баннер «есть обновление» (04 §6.3)

```
╭──────────────────────────────────────────────────────────────────────╮
│ ⬆ Доступна версия 1.4.2 — исправлен бейдж непрочитанных   [Перезапустить] [Позже] │
╰──────────────────────────────────────────────────────────────────────╯
```

Неблокирующая полоса под шапкой (subtle-фон `#d8f3d8`). Обновление никогда не ставится без
клика (у оператора может быть недописанный ответ); «Позже» прячет до следующего старта
(повтор через 24 ч). «Перезапустить» — скачивание, проверка подписи, тихая установка,
перезапуск; outbox не теряется (SQLite).

### 8.3. «Нет доступа» (403)

Два разных случая:

1. **Прямая ссылка на чужой раздел** (например, M открыл `/stats` по ссылке из мессенджера):
   route-guard тихо редиректит в `/chats` (03 §6 — пункта меню пользователь и так не видел,
   страница-тупик не нужна).
2. **Право пропало на лету** (роль сменили среди сессии; API вернул `403 forbidden` на
   открытом экране): полноэкранная заглушка в зоне контента —

```
┌────────────────────────────────────────────┐
│                 🔒                          │
│         Нет доступа к этому разделу         │
│  Ваши права изменились. Обратитесь к        │
│  администратору, если это ошибка.           │
│            [Перейти к чатам]               │
└────────────────────────────────────────────┘
```

   Одновременно фронт перезагружает `GET /auth/me` и перестраивает NAV. Частный случай
   `403 read_only_role` (H нажал отправку через старый UI) — не заглушка, а плашка
   «Режим просмотра» (§2.5.2). `401` — стандартный refresh-флоу, при провале — `/login`.

### 8.4. Глобальный поиск (Ctrl+K)

Единая точка поиска — поле списка диалогов (отдельного поискового API нет — контракт
`GET /conversations?q=`, 01 §5.1):

- `Ctrl+K` внутри `/chats` — фокус в поле; на любом другом экране — переход в `/chats`
  с фокусом в поиске (черновики и состояние экрана не теряются — обычная навигация).
- Ищет по всем диалогам независимо от активной вкладки (вкладки на время поиска затемнены);
  совпадения по имени/телефону подсвечиваются в строке; для полнотекстовых совпадений строка
  показывает стандартное последнее сообщение (сниппетов API не отдаёт — честное ограничение
  MVP).
- `Esc` — очистить и вернуть вкладку. Пусто/ошибка — §8.2 / стандарт.
