# Лид-бот автоответом в LeadChat (ТЗ на стык двух систем)

Техническое задание на подключение лид-бота к LeadChat в режиме автоответа.
Написано по коду ОБЕИХ систем (LeadChat — эта ветка; лид-бот — `~/Work/Лид-бот`,
состояние на 12 августа 2026).

**Главное, что надо знать перед чтением: ручка на стороне лид-бота УЖЕ ЕСТЬ.**
Это не заказ «сделайте нам интерфейс», а фиксация того, что уже написано, плюс
короткий список того, чего в нём не хватает (§7). Со стороны LeadChat работа
закончена и лежит в `app/bots/leadbot.py`, `app/bots/provider.py`, миграция 0035.

---

## 1. Что меняется для человека

Сегодня лид-бот работает через Jivo в режиме «человек в контуре»: он предлагает
ответ, оператор его отправляет. После подключения он отвечает клиенту сам,
LeadChat отправляет ответ в Авито, и бот замолкает, как только в диалог написал
менеджер.

Всё остальное поведение LeadChat остаётся как было и НЕ переизобретается:

| Что | Где живёт | Меняется? |
|---|---|---|
| Замолкание при менеджере | `app/bots/runtime.py::_run_tick` → `mute_bot` | нет |
| Расписание работы бота | `app/bots/schedule.py` | нет |
| Передача человеку (handoff) | `app/bots/engine.py::do_handoff` | нет |
| Лимиты сообщений подряд, защита от зацикливания | `app/bots/steps.py::Limits` | нет |
| Метка «негатив», распознавание «позовите человека» | `app/bots/ai.py::classify_message` | нет, остаётся нашим |
| **Текст ответа клиенту на шаге `ai_answer`** | было `app/bots/ai.py` | **да — теперь лид-бот** |

Подменяется ровно одна вещь — кто сочиняет ответ. Классификатор и извлечение
сущностей перед передачей остаются на Claude: у лид-бота таких ручек нет, и если
бы мы просто перестали их звать, диспетчеры молча потеряли бы метку «негатив» и
подсказки в карточке передачи — потерю, которую никто не связал бы с включением
автоответа.

## 2. Точка стыка

```
Авито → вебхук → LeadChat: тик бота (app/bots/runtime.py)
                    │
                    └─ шаг сценария `ai_answer`
                         │
                         ├─ bots.ai_provider = 'claude'  → app/bots/ai.py    → Anthropic
                         └─ bots.ai_provider = 'leadbot' → app/bots/leadbot.py → HTTP → лид-бот
                                                                    │
                              None (таймаут / отказ / мусор) ───────┘
                                   ↓
                              handoff человеку, доставка сообщений НЕ блокируется
```

Развилка — `app/bots/provider.py`. Движок сценариев (`app/bots/engine.py`) о
существовании лид-бота не знает вовсе: он зовёт
`ai_answer(bot, dialog, item_title)` и разбирает результат.

## 3. Контракт ручки

### 3.1 Запрос

```
POST {LEADBOT_URL}/api/leadchat/answer
Authorization: Bearer <служебный токен>
Content-Type: application/json
```

Тело:

```json
{
  "dialog": [
    {"role": "user",      "content": "Разбил экран на айфоне 13, сколько будет?"},
    {"role": "assistant", "content": "Здравствуйте! Уточните, пожалуйста, модель."}
  ],
  "item_title": "Ремонт iPhone",
  "client_name": "Иван",
  "city": "",
  "request_id": "85e578d88635ef8b1b87d9a49e03ca39"
}
```

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `dialog` | массив объектов | да | Последние реплики переписки, СТАРЫЕ СНАЧАЛА. `role`: `user` — клиент, `assistant` — бот или оператор. Сколько реплик — задаётся в шаге сценария (`context_messages`, по умолчанию 10) |
| `item_title` | строка | да (может быть пустой) | Заголовок объявления Авито, по которому пишет клиент |
| `client_name` | строка | да (может быть пустой) | Имя клиента, если Авито его отдал |
| `city` | строка | да (может быть пустой) | Сейчас всегда пусто — см. §7.2 |
| `request_id` | строка | да | Ключ идемпотентности, см. §5 |

Пустой `dialog` LeadChat не отправляет вовсе: спрашивать нечего — не спрашиваем.

### 3.2 Ответ

```json
{
  "reply": "Замена экрана iPhone 13 — ориентировочно от 8900 ₽, точнее после диагностики.",
  "confidence": 0.9,
  "needs_operator": false,
  "meta": {"layer": "модель", "ms": 1200}
}
```

| Поле | Тип | Обязательно | Требование |
|---|---|---|---|
| `reply` | строка | **да** | Текст клиенту. Может быть пустым, но обязан БЫТЬ и обязан быть строкой. `null` — нарушение контракта |
| `confidence` | число 0..1 | **да** | Именно число. `true`, `"высокая"`, `null` — нарушение контракта |
| `needs_operator` | булево | **да** | Именно `true`/`false`. `"yes"`, `1` — нарушение контракта |
| `meta` | объект | нет | Побочные сведения, движку не нужны; LeadChat пишет часть из них в журнал (§6.2) |

Значения вне 0..1 LeadChat прижимает к границам, а `reply` режет по 1000
символов — но это страховка от чужой ошибки, а не разрешение.

### 3.3 Как LeadChat читает ответ

Это самое важное для той стороны: от трёх полей зависит, увидит ли клиент текст.

| Что пришло | Что делает LeadChat |
|---|---|
| `needs_operator=false`, `confidence ≥ порога` (0.6) | **Текст уходит клиенту**, сценарий идёт дальше |
| `needs_operator=true`, `reply` непустой | **Текст уходит клиенту** как фраза-мост, затем handoff |
| `needs_operator=true`, `reply` пустой | Клиент не получает ничего, диалог у человека |
| `confidence < порога` | Handoff, и **текст клиенту НЕ уходит** — даже хороший |
| `None` (см. §3.4) | Заметка «AI недоступен», handoff, ретраев нет |

**Отсюда практическое следствие для лид-бота: занижать уверенность у хорошего
ответа нельзя.** Ответ с `confidence=0.5` будет выброшен целиком, и клиент
увидит молчание до прихода человека. Роутеры (детерминированные) — 1.0, ответ
модели после гардов — 0.9; обе величины выше порога, и это правильно.

### 3.4 Коды ответа

| Код | Когда | Что делает LeadChat |
|---|---|---|
| `200` | Есть ответ (в том числе «нужен оператор») | Разбирает по §3.2 |
| `400` | Разбор запроса не удался | `None` → handoff |
| `401` | Токен не подошёл или не задан | `None` → handoff, в журнале `leadbot.rejected` |
| любой другой | — | `None` → handoff, в журнале `leadbot.bad_status` |

Отдавать `500` на внутреннюю ошибку **не нужно**: для клиента в чате пятисотка
выглядит ровно так же, как молчание. Правильнее ответить `200` с пустым `reply`
и `needs_operator=true` — тогда причину передачи назначает лид-бот осмысленно, а
не наш секундомер. Ручка так и написана (`leadchat.unavailable`).

## 4. Сроки

| Кто | Сколько | Где |
|---|---|---|
| Лид-бот обязан ответить | **9 секунд** | `LEADBOT_ANSWER_TIMEOUT_S`, `brain/leadchat.py::timeout_s` |
| LeadChat перестаёт ждать | **10 секунд** | `AI_TIMEOUT_SECONDS`, `app/core/config.py` |

Секунда разницы — это запас на сеть, и она намеренно на стороне лид-бота: он
должен успеть решить «не успеваю» сам. Если поднимать `LEADBOT_ANSWER_TIMEOUT_S`
выше 9, надо поднимать и `AI_TIMEOUT_SECONDS` — иначе решение о передаче человеку
начнёт принимать наш таймер, и в журнале лид-бота этих случаев не будет видно
вовсе.

**Повторов НЕТ ни одного.** Это решение владельца №4 (DESIGN §4.5): недоступность
ИИ никогда не блокирует доставку сообщений. Повтор внутри того же бюджета удвоил
бы время ожидания и увеличил шанс, что клиент не получит ничего.

## 5. Идемпотентность

`request_id` — sha256 от идентификатора бота и содержимого `dialog`, первые 32
символа (`app/bots/leadbot.py::_request_id`).

Свойства, на которые можно опираться:

* повторный POST того же тика приходит с ТЕМ ЖЕ `request_id` — можно отдать
  ответ из кэша, не тратя вызов модели;
* как только клиент написал ещё раз, `dialog` изменился и ключ стал другим —
  кэш не отдаст старый ответ на новое сообщение.

Идентификатора диалога в ключе нет, потому что его нет в протоколе `ai_answer`:
туда приходят бот, реплики и заголовок объявления. Если он понадобится лид-боту
для чего-то ещё — см. §7.1.

Лид-бот держит кэш 10 минут, до 500 записей (`brain/leadchat.py`), и помечает
повтор как `meta.repeat=true`.

## 6. Включение и эксплуатация

### 6.1 Как включить

1. **Задать адрес и токен.** Хранятся в базе (`app_settings`, ключ `leadbot`),
   токен — в шифрованном виде. Запасной вариант — переменные окружения
   `LEADBOT_URL` и `LEADBOT_TOKEN`; они задают стартовое состояние при
   развёртывании, а из интерфейса значение переопределяется без захода на
   сервер. Программный доступ — `app/bots/leadbot.py`: `save()`, `load()`,
   `reset()`, `safe_dump()`.
   ⚠ Токен — только латиница и цифры. Русская «с» вместо латинской ломает
   заголовок HTTP ещё до сети, и снаружи это выглядит как «лид-бот недоступен» на
   каждом диалоге. `save()` такой токен не примет.
2. **Включить в разделе «Настройки → Лид-бот».** С 12 августа это отдельная
   сущность со своим экраном, а не выбор «мозга» у обычного бота: решение
   владельца — «сам LeadBot это не совсем бот». Экран делает три вещи, которых
   раньше не было нигде: меняет адрес и токен без выкатки, даёт тестовый
   разговор (никого не задевая) и показывает журнал работы.
   Служебный слой — `app/services/leadbot_admin.py`, ручки — `/api/v1/leadbot*`.
3. **Проверить тестовым разговором ДО включения.** См. §8.

**Заполненность `LEADBOT_URL`/`LEADBOT_TOKEN` сама по себе не включает ничего.**
Раньше включала: воркер видел непустую пару и молча переводил на лид-бота всех
ботов разом. У лид-бота свой регламент, свои цены и свои формулировки — менять
то, что читают клиенты, одной переменной окружения нельзя.

### 6.2 Что видно в журнале

| Событие | Когда | Что означает для человека |
|---|---|---|
| `leadbot.unavailable` | не дозвонились, таймаут | Диалог ушёл человеку; смотреть сеть и живость лид-бота |
| `leadbot.rejected` | 401 | Токен разошёлся. Чинится настройкой, не перезапуском |
| `leadbot.bad_status` | другой код | Лид-бот жив, но отвечает ошибкой |
| `leadbot.bad_json`, `leadbot.bad_shape` | ответ не той формы | Нарушен §3.2 — чинить на стороне лид-бота |
| `leadbot.escalation` | `meta.escalation` | Причина и срок реакции для очереди людей |
| `leadbot.lead_ready` | `meta.lead_ready` | Заявка собрана. Пишутся ТОЛЬКО имена полей: в `meta.lead` лежит телефон, а журнал читают шире переписки |
| `leadbot.warning` | `meta.warnings` | Предупреждения лид-бота — см. §7.1 |
| `bot.leadbot_not_configured` | бот переключён, адреса нет | Диалоги уходят людям, пока не заполнят настройку |

**Токена нет ни в одной строке журнала, ни в `repr` объектов, ни в
`safe_dump()`.** Это проверяется тестами по всем путям отказа сразу
(`tests/unit/test_bot_leadbot.py`), потому что течёт секрет обычно не в успешном
сценарии, а в диагностике.

### 6.3 Что будет при отказе

Любой отказ — таймаут, обрыв, 401, 500, не-JSON, JSON не той формы — даёт один и
тот же результат:

1. диалог получает заметку «🤖 AI недоступен, передал диалог менеджеру»;
2. бот замолкает, диалог уходит в общую очередь с причиной `ai_unavailable`;
3. **уже отправленные сообщения этого тика доходят до клиента** — приветствие,
   заданный вопрос, всё, что успело уйти до шага `ai_answer`;
4. повторов нет; следующее сообщение клиента бот уже не обрабатывает — диалог
   ведёт человек.

Пункт 3 — единственное, ради чего написана вся осторожность в
`app/bots/leadbot.py`, и он покрыт сквозным тестом
`test_a_silent_leadbot_never_blocks_delivery`.

Если бот переключён на лид-бота, а адрес или токен не заданы, LeadChat **не
откатывается на Claude молча**. Ответить вместо лид-бота нашим мозгом значит
выдать клиенту цены и формулировки, которых владелец не согласовывал, и не
заметить этого. Передача человеку заметна и чинится настройкой.

## 7. Что осталось доработать

### 7.1 Телефоны уходят лид-боту СЫРЫМИ — решение принято 16.08.2026

**ЗАКРЫТО.** Раздел оставлен на месте: на него ссылаются шапка
`app/bots/leadbot.py` и другие документы, а история решения важнее аккуратности
нумерации.

**Что решено.** Маскировка снята — но ровно для одного адресата. Лид-боту диалог
уходит как есть, живыми номерами; всякой другой модели `load_dialog_for_ai`
по-прежнему заменяет их на `{PHONE}`. Развилка — одна строка в
`engine._ai_request`:

```python
dialog = await self.load_dialog_for_ai(context_messages, mask=provider_of(self.bot) != LEADBOT)
```

**Почему.** С маской воронка не видела уже данный клиентом телефон и просила его
повторно — самый заметный признак робота; лид-бот сам предупреждал об этом в
`meta.warnings`. Размен назван честно: адресат — сервер владельца в его же
контуре (`LEADBOT_URL`, приватный адрес за мостом WireGuard), запрос за периметр
не уходит. Для Claude маска остаётся обязательной: тот запрос идёт за границу
через прокси.

**Чем закреплено.** Коммит `906a6e8` от 16.08.2026 «Лид-боту — сырые телефоны и
полная история». Сторож — `tests/unit/test_bot_leadbot.py::test_лид_бот_видит_телефон_сырым`:
требует живой номер в теле запроса и отсутствие `{PHONE}`.

**Что это НЕ отменяет.** В наш собственный журнал (`leadbot_calls.question`)
телефон не попадает: `engine._record_leadbot` маскирует вопрос при записи,
отдельным вызовом. Проверено на бою 23.08.2026: из 726 записей журнала ни одной
с настоящим номером.

### 7.2 Поля, которые лид-бот умеет принимать, а LeadChat не шлёт

`brain/leadchat.py::parse_request` разбирает ещё `direction`, `persona`,
`partner`, `white`, а `city` LeadChat отправляет всегда пустым, потому что города
на боте нет (есть на объявлении и на аккаунте). Из них важнее всего:

* **`persona`** — имя мастера. Без него модель придумывает его сама, и в разных
  диалогах одного аккаунта оно разное. Это заметно клиенту.
* **`city`** — от него зависит выбор филиала и territory-логика лид-бота.

Обе величины в LeadChat есть, но не на боте: город — у объявления и аккаунта,
имя мастера — нигде. Чтобы их передавать, нужно решить, где они живут (поля
бота? поля канала?), и это отдельная задача — в этот стык она не входит.

### 7.3 Песочница проверяет сценарий, а не мозг

Редактор ботов (`app/bots/sandbox.py`, режим «real») всегда ходит в Claude, даже
если бот переключён на лид-бота. То есть проверить в песочнице, ЧТО именно
ответит лид-бот, сегодня нельзя — проверяется только сценарий вокруг.

Чинится передачей `ai_provider` в сессию песочницы; требует правок в
`app/api/routes/` и во фронте, поэтому вынесено отдельно. **До того как это
сделано, первую проверку лид-бота надо делать на живом диалоге одного бота
(§8), а не в песочнице.**

### 7.4 Экрана настройки ещё нет

`app/bots/leadbot.py` даёт `save()`/`load()`/`reset()`/`safe_dump()`, но ручки
API и экрана к ним нет — адрес и токен сейчас задаются через `LEADBOT_URL` и
`LEADBOT_TOKEN`. Экран делается по образцу ключей приложения Авито
(`app/services/avito_app.py` + `app/api/routes/`): токен наружу не возвращается
никогда, отдаётся только «задан / не задан», а `token=None` означает «оставить
прежний».

## 8. Порядок первого включения

Автораздача выключена, на смене один человек (см. `docs/41`), поэтому
осторожность здесь не формальная.

1. **«Настройки → Лид-бот» → задать адрес и токен → «Проверить связь».**
   Пока связи нет, включить нельзя: кнопка заперта, и рядом сказано почему.
2. **Тестовый разговор.** Спросить пять-шесть типовых вопросов и посмотреть
   ответы. Никто ничего не получает — ни клиент, ни журнал работы. Смотреть на
   слой: `роутер` значит сработал регламент, `модель` — думала модель.
3. **Режим «подсказка», ОДИН канал, включить.** Ответы лягут заметками
   оператору; клиент не получит ничего. Действующих ботов это не трогает — у
   лид-бота своя запись, и в списке ботов её нет.
4. **Посмотреть журнал на том же экране.** Он отвечает на вопрос, которого не
   было в логах: чем обращение кончилось ДЛЯ КЛИЕНТА. «Ответ отброшен — низкая
   уверенность» и «лид-бот не ответил» для клиента одинаковое молчание, и
   ловятся они только здесь.
5. **Проверить отказ намеренно:** погасить лид-бота и убедиться, что диалог ушёл
   человеку с заметкой «AI недоступен», а не завис.
6. Только после недели в подсказках — думать про автоответ.

Обратный ход — одно нажатие «Выключить лид-бота». Перезапуск не нужен, миграция
не откатывается, ничего не теряется.
