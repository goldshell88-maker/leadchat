# LeadChat

Рабочее место для переписки с клиентами Авито: все аккаунты компании в одном
окне, распределение диалогов между операторами, карточка клиента, которая
заполняется сама (телефон и адрес из переписки, адрес сверяется с картой),
боты первичного приёма, статистика и уведомления. Работает в бою: веб-кабинет
и настольное приложение для Windows.

Архитектура и контракты — [DESIGN.md](DESIGN.md) и ТЗ в [docs/](docs/).

## Что умеет

- **Единый поток чатов.** Сообщения всех подключённых аккаунтов Авито в одной
  ленте и таблице диалогов; вложения и голосовые (расшифровка включается
  настройкой), быстрые ответы, закрепы, горячие клавиши, отметки прочтения.
- **Распределение и передача.** Диалоги раздаются операторам по правилам и
  потолку нагрузки; передача коллеге, возврат, «люди × каналы» — кто какие
  аккаунты ведёт.
- **Карточка клиента.** Телефон и адрес выезда достаются из переписки,
  адрес проверяется картой (DaData, Яндекс, OpenStreetMap через шлюз),
  двойники одного клиента склеиваются, суть обращения — краткой сводкой.
- **Боты.** Редактор сценариев (сообщение, меню, вопрос, ответ модели,
  закрытие) с песочницей, режим подсказок оператору, связка с внешним
  лид-ботом, надзор за диалогами ботов.
- **Статистика.** Нагрузка и скорость ответа по людям и каналам, графики,
  повторные клиенты.
- **Уведомления.** Браузерные уведомления и звук — только тому, кого
  касается сообщение.

## Как устроено

| Каталог | Что внутри |
|---|---|
| `app/` | бэкенд: FastAPI (REST + WebSocket), SQLAlchemy async, PostgreSQL, Redis |
| `app/workers/` | ARQ-воркеры: приём и доставка сообщений, геокодинг, расшифровка голосовых, склейка клиентов |
| `app/scheduler/` | задачи по расписанию: статистика, сторож каналов, дедлайны ботов, догон пропущенных прогонов |
| `app/bots/` | движок сценариев ботов |
| `frontend/` | веб-кабинет: React 18 + Vite + Mantine |
| `desktop/` | настольное приложение на Tauri (Windows), с автообновлением |
| `gateway/` | шлюз внешних API (карты, подсказки адресов, модели) — отдельный сервис, [docs/46](docs/46-ШЛЮЗ-API.md) |
| `fake_avito/` | имитатор API Авито для разработки и тестов |
| `deploy/` | выкатка, резервные копии, проверки после выкатки |
| `tests/` | unit (SQLite + fakeredis) и integration (PostgreSQL в testcontainers) |

## Запуск за 10 минут

Предпосылки (на macOS всё ставится через Homebrew):

- **Docker** (Docker Desktop / OrbStack) — для postgres, redis и мока Авито;
- **uv** — менеджер Python-окружения; Python ставит сам: `uv python install 3.12`;
- **Node.js 20+ и npm** — для фронтенда.

```bash
# 1. Конфиг: dev-значения работают из коробки
cp .env.example .env

# 2. Инфраструктура: postgres :5432, redis :6379, fake-avito :8020
make dev

# 3. Схема БД
make migrate

# 4. Первый админ (CLI спросит email/пароль; флаги — python -m app.cli create-admin --help)
make seed

# 5. Бэкенд с hot-reload: http://localhost:8000 (health: /api/health)
make api

# 6. Фронтенд (отдельное окно терминала): http://localhost:5173
make fe-dev
```

Логин: откройте <http://localhost:5173> и войдите под учёткой, созданной на шаге 4.

Фоновые процессы — каждый в своём окне терминала:

```bash
make worker      # ARQ-воркер: приём сообщений и фоновые задачи
make scheduler   # задачи по расписанию
```

Полностью контейнерный режим (api + worker + scheduler в Docker):
`docker compose -f docker-compose.dev.yml up -d`.

## Полезные команды

| Команда | Что делает |
|---|---|
| `make test` | unit-тесты (без внешних сервисов) |
| `make test-int` | integration-тесты (testcontainers, нужен Docker) |
| `make lint` | ruff + mypy |
| `make fe-build` | production-сборка фронтенда |
| `make seed-avito` | насыпать историю в fake-avito для проверки догона истории |
| `make down` | остановить dev-инфраструктуру |

Мок Авито (`fake_avito/`) слушает на `http://localhost:8020` — бэкенд смотрит в него
через `AVITO_API_BASE` из `.env`; сброс состояния: `POST /_control/reset`.
Входящее сообщение с доставкой вебхука: `POST /_control/incoming` (см. `fake_avito/main.py`).

## Выкатка

`deploy/workstation/ship.sh` — одна команда с рабочей машины: линтеры, типы и все
наборы тестов, проверка секретов на сервере, снимок базы до миграций, сборка
образов на сервере с меткой отката, миграции, перезапуск, строгая проверка боя
снаружи (SM-1…16) и откат образов при провале. Порядок и аварийные случаи —
[docs/RUNBOOK-DEPLOY.md](docs/RUNBOOK-DEPLOY.md) и [docs/05-DEPLOY-OPS.md](docs/05-DEPLOY-OPS.md).
